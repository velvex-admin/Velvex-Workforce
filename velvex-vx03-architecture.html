Orchestration Layer

One coordinating role, not a separate agent for every function that touches memory — a "memory agent" on top of this would just watch the same database twice.

Chief-of-Staff Agent

Every other agent reports to it: what it did, what it wants to do next. It filters — routine updates get logged to the reports table; anything that looks like a new idea or a problem gets written to the pending-approvals table for you to review. It queries its own memory store when it needs context on something, rather than you checking each agent individually.

Autonomy Boundary — General Rule

One principle, applied per agent above with its own specifics: routine means anything inside an already-approved channel, budget, and scope — it runs with no permission needed. Needs approval means anything new — a new channel, spending money, a pricing or messaging change, contacting someone outside the normal flow, or any action that can't be undone. A few agents sit off this default because the cost of a wrong autonomous move is higher for them specifically — the SEO agent's live-page edits and the engagement agent's replies to criticism are both drawn tighter than their batch-mates for that reason.

Voice Requirement

"As human as possible" is a real build requirement here, not a tone note — the content agent and the social engagement agent are the two that write in your business's voice in public, so both get built against an actual voice profile rather than a generic "sound friendly" instruction, which is what produces the robotic AI tells (em dashes and all) you're trying to avoid.

Two ways to build the voice profile

Your call

Option A: you supply a handful of things you've actually written — emails, posts, even voice-note transcripts — and it gets turned into a style guide the two agents are built against.

Option B: skip that step for now — a natural, deliberately non-AI-sounding default voice gets drafted, and you correct it once you see it in action.

Build & Deployment

This is a one-off build, not a recurring job — the right tool is a Claude Code cloud session, not a scheduled Routine and not Dispatch.

Project pushed to GitHub (if not already)
→

→
Runs on Anthropic's infrastructure, independent of your laptop
→
Checked from the Claude mobile app whenever you want

Closing the laptop mid-build is safe with this path. Opening a plain Claude Code terminal session and closing the terminal, or using Dispatch with the machine off, are not — both depend on something on your end staying on.
